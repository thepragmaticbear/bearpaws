# Bearpaws v2.6.1 — the risk gate, hardened by live use

This patch release closes the gaps found when the 2.6.0 risk gate was measured and then used in live sessions. The gate stays on by default. It now speaks as feedback instead of a hook error, sees edits made through Bash, and doesn't loop on test-only follow-ups.

**Requires Claude Code 2.1.163 or later** for enforcement. On older builds the gate does nothing (fails open). It also needs `jq`. Set `BEARPAWS_ENFORCE=0` to turn it off.

## Risk gate (`hooks/risk-gate`)

- **Stop feedback, not a hook error** (#25). When the gate catches a missing receipt or review, it returns Claude Code's non-error Stop feedback (`hookSpecificOutput.additionalContext`). The turn continues until the agent adds the receipt, with the same loop protections as before, and no "Stop hook error" is shown.
- **Bash edits count** (#24). Edits made through the Bash tool (`cat > file`, `sed -i`, `python -c`, …) are detected in git repos by a fingerprint of the work tree. It records path, size and modification time for tracked and untracked files, keyed by the repo's top-level directory.
  - `git add`, `git commit`, `cd` and switching between worktrees are not edits.
  - Caches and common test artifacts are ignored.
  - A PreToolUse hook takes the first fingerprint before the first Bash call.
- **Fixes after a review need a re-review** (#24). Because Bash edits now count, "a review after the last edit" covers every edit method, so a fix made after a review needs a new one.
- **Re-reviews sent by message count** (#26). A `SendMessage` to a reviewer counts as a review when its summary matches the review rule and it isn't addressed to `main`.
- **Test-only follow-ups don't loop** (#26). Edits to test files (relative paths under `tests/`, `test/` or `__tests__/`, or conventional test file names) still need a receipt. They don't restart the review requirement; production edits and Bash edits still do.

## Benchmark tooling

- **Per-session timeout** (#23). `--session-timeout` (default 900 s) runs each session under a supervisor. On every exit path it kills the session's whole process tree, including processes that called `setsid`, and it checks each process's start time before killing so it never hits an unrelated process.
- **Status read across all replies** (#23). The scorer decides INCOMPLETE from the last `Status:` line across all of a session's replies. An addendum to the escaped-defect write-up rescores earlier runs under this rule; the pre-registered headline is unchanged.

## Evidence

- **Measurement of #23/#24** on the frozen risk suite (Bearpaws only, 30 runs): 3/30 escaped defects (unchanged), 3 timeouts, and 17% higher cost.
- **Live test matrix**, 12 sessions with plain task prompts:
  - Q&A and routine edits pass with no review.
  - A sensitive-looking path gets one nudge and no loop.
  - Elevated work, whether edited with tools, through Bash, or by a subagent, ends COMPLETE only after a review.
  - A test-only follow-up after a review doesn't force a second one.
  - In every elevated case, the agent first claimed COMPLETE after fixing review findings. The gate sent it back for a re-review each time.
- Details are in `docs/bearpaws/plans/2026-10-12-followups-design.md`.

## Known limits

The full list is in `docs/bearpaws/plans/2026-10-11-risk-gate-design.md` §5. The main ones:

- The sensitive-path nudge can't see paths changed through Bash, and a Bash edit is never treated as test-only.
- Any growing untracked file inside the repo counts as an edit.
- An agent that waits on a background review with `ScheduleWakeup` can be slow; in headless runs it can hang until the timeout.
- Elevated work left INCOMPLETE stays pending for the rest of the session.
