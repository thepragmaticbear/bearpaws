# Bearpaws v2.8.0 — receipts checked against what the session did

This release makes the Claude Code risk gate check more of the receipt against the session log. Unfixed review findings now keep work INCOMPLETE, and receipts gain a `Not checked:` line. A new pre-push hook flags commit emails that would publish a personal address.

## Risk gate (`hooks/risk-gate`, `hooks/session-start`) (#40, #45)

- **Test edits restart the review.** On elevated work, a test-file edit after the last review needs a new review or `Status: INCOMPLETE`. A test edit can weaken what the reviewer saw.
- **Test runs are logged.** A Bash command that starts a test runner logs a `test-run`. Wrappers such as `uv run`, `npx`, `bundle exec`, `docker compose exec` and `timeout` are recognized. A command that only mentions a runner (`echo pytest`, `cat tests/x.sh`) does not count.
- **`Verified:` claims are checked.** A `Verified:` line that claims a test run is blocked when no run followed the last edit. The line is read clause by clause, split on `;`, `,`, parentheses and sentences. So `shellcheck passed; tests not run` is not a claim, and `41 passed (e2e not run)` is one.
- **`Pinned:` claims are checked.** A `Pinned:` line that claims tests passed before the edit is blocked when no run came before the first edit. `none`, `n/a`, `there were no tests` and similar wording are not claims.
- **Honest INCOMPLETE is never blocked** by either check.
- **Inactive notice.** When `BEARPAWS_ENFORCE=0` is set or `jq` is missing, the session starts with one line saying the gate is off.

## Review findings and scope (#42)

- **Reviewers ignore the author's scope claims.** A same-risk-class defect is judged against the task and the diff, whatever the report calls out of scope.
- **New `Open:` receipt line.** It lists each Critical or Important finding left unfixed. `Status: COMPLETE` needs exactly `Open: none`, and a finding your human partner deferred is still open.
- **Hook enforcement.** The hook blocks an elevated COMPLETE whose `Open:` is missing or lists anything. Elevated INCOMPLETE work with an open finding stays pending: a later reply with a receipt is judged again, and a reply with no receipt lines passes.
- `tests/review-eval` gains the `refund-scoped` and `refund-offscope` fixtures.

## Receipt evidence (#41)

- **New `Not checked:` line.** It names every check you did not run, or `none`. Routine receipts are now `Risk`, `Verified`, `Not checked` and `Status`.
- **"Tests pass" evidence.** It needs the test count before and after your edit, or `no baseline`. If added tests didn't change the count, say so.
- **Moves and refactors.** A pure move or refactor needs a diff of the moved code only. A whole-file diff or `--stat` is not enough.

## Commit identity check (#44)

- **New `pre-push` hook**, installed by `./install.sh --git` next to `commit-msg`. It flags pushed commits whose author, committer or `Co-authored-by` email is neither a GitHub noreply address nor on the project's `Allowed commit emails:` line.
- **Each branch is flagged once,** with a rewrite command. Commits any remote already has are not checked.
- **Skill.** `finishing-a-development-branch` runs the same check before merge or PR options. It never rewrites without your human partner's choice.

## Privacy (#43)

- `/Users/<name>` paths in docs, skills and tests are replaced with `~` or `$HOME`.
- Reviewers redact emails, home paths, hostnames and tokens before writing any review artifact.
- The PR template gains a checkbox: no personal emails, home paths or tokens in transcripts or logs.

## Known limits

- Claim detection is wording-based. `suite passed` with no count, `the tests are all green` and `41/41 green` are missed. A wrapper option that takes a value (`docker run -e X=1 img pytest`, `make -C dir test`) hides the runner.
- A production fix made through Bash before any Edit-tool edit is not counted as the first edit for `Pinned:`.
- `git push --dry-run` uses up a branch's one-time identity flag.
- The redaction rule and the onboarding note on `Allowed commit emails:` had no RED baseline: agents already complied.
