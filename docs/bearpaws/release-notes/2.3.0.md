# Bearpaws v2.3.0 — Current Agent Tooling & Experimental Codex Wiring

This release brings skill text and hooks in line with current Claude Code tooling and adds an experimental Codex install flow built on native Agent Skills discovery.

## Why 2.3.0

- Claude Code renamed its subagent tool from `Task` to `Agent` (2.1.63) and replaced `TodoWrite` with `TaskCreate`/`TaskUpdate`/`TaskGet`/`TaskList`. On some current models those task tools are gated off entirely, so skills that *required* a todo tool could stall.
- Context compaction drops the SessionStart bootstrap, and the hook did not re-run on `compact`.
- Codex now discovers `SKILL.md` directories from `.agents/skills/` natively, so Bearpaws can reach it with a thin symlink adapter instead of no install flow.

## What changed

### Claude Code
- `hooks/hooks.json` SessionStart matcher is now `startup|clear|compact`, so the bootstrap is re-injected after compaction. `resume` stays excluded: the resumed transcript already carries the bootstrap, and re-injecting would stack duplicate copies.
- Subagent dispatch text names the `Agent` tool (formerly `Task`) in `requesting-code-review`, `dispatching-parallel-agents`, and all reviewer/implementer prompt templates.
- `executing-plans` and `subagent-driven-development` track progress with a task list (`TaskCreate`/`TaskUpdate`, legacy `TodoWrite`) and fall back to the plan's own checkboxes when no task tool is available.
- Tests accept both old and new tool names; the SDD integration test accepts ticked plan checkboxes as task tracking.

### Codex (experimental)
- Added `./install.sh --codex` (repo-local `.agents/skills/`) and `--codex --global` (`~/.agents/skills/`). `--all` and the no-argument default now include Codex.
- Added committed `.agents/skills/` symlinks for working in this repo.
- Added a one-line Codex activation step to `using-bearpaws`.
- No Codex SessionStart hook: Codex currently rejects injected `additionalContext`. Docs recommend an `AGENTS.md` line to load `using-bearpaws`.

### Installer safety
- Symlink reconciliation previously deleted *every* symlink in a target directory if any one was broken. It now prunes only broken links that pointed into Bearpaws' `skills/`, and skips any colliding entry that is not a Bearpaws link (a real directory or the user's own symlink). This matters for shared global directories (`~/.agents/skills`, `~/.config/devin/skills`).

## What did not change

- Support tiers: Claude Code and Google Antigravity IDE remain primary; Codex, Devin for Terminal, and Windsurf Cascade remain experimental.
- Red Flags, rationalization tables, Pace Control, and brevity policy wording are unchanged.
- Skill frontmatter already conforms to the Agent Skills `name`/`description` constraints; no skill was renamed.

### Fixes
- `install.sh` and `tests/antigravity/run-adapter-tests.sh` used `((x++))` under `set -e`, which aborts when `x` is 0. The Antigravity adapter test exited early on every run, and failed installs exited before printing their error summary. Both now use `x=$((x + 1))`.
- `tests/install/run-install-tests.sh` is now executable, matching how `CLAUDE.md` invokes it.
- README token table updated to the measured bootstrap size (~6.4 KB). It had drifted since v2.2.0 added Pace Control and is now larger than the superpowers reference, not smaller.
