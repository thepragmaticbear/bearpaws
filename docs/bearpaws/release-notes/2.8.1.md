# Bearpaws v2.8.1 — a reproducible diff-size metric

This release changes no skill, template or hook. It adds the measurement and evals from an attempt to cut over-building with a reuse-first, scoped-simplification change. The attempt did not reduce diff size, so its skill edits were reverted. The [write-up](../../benchmarks/2026-11-04-diff-size-reuse.md) has the full result.

## Result

Against a concurrent `main` control arm, on the six elevated-risk tasks:

- **Code-only bloat:** 1.44× for the candidate, 1.46× for the control. The target was 1.1×.
- **Escapes:** 5 of 30 for the candidate, 4 of 30 for the control. Negative refunds stayed at 0.
- **Routine cost:** $0.126 against $0.109 per task, mostly from one scenario that dispatched a review in every candidate run.

The bloat that remains is style, not defensive guards: two `if` statements where the reference fix writes one compound condition, and SQL layout.

## Measurement (`tests/benchmark`)

- `summarize.py` reports `code_added`, `ref_code_added` and a `code bloat` column: added lines with blank, comment and docstring lines dropped. The earlier 1.4× figure came from a one-off script on work trees that no longer exist. This one is reproducible.
- `code_lines()` and `added_lines()` live in `summarize.py`, and the risk-eval and reuse-eval scorers import them.
- Comparisons now run a `main` control arm in the same batch (`--arms "control=<dir> bearpaws"`). This removes Claude Code version drift between runs.

## Evals

- **New `tests/reuse-eval`:** a routine feature that needs an existing `parse_cents` helper, next to an untidy function the task must leave alone. It scores helper reuse, reimplementation, type guards and diff scope.
- **New review-eval `FIXTURE=reimplemented`:** a correct hand-rolled parser next to an existing helper that already does the job. `test_score.py` covers its scorer key.

## Reverted

- **Reuse-first TDD wording:** type guards on reuse-eval went from 1 of 3 runs to 2 of 3.
- **Reviewer finding for reimplementing an existing function:** detection on its fixture went from 3 of 9 runs to 7 of 9. It fired in 1 of 57 benchmark runs while reviewer searches roughly doubled, so it added review work with no diff-size return.

A bootstrap reuse clause was not written: reuse-eval already reused the helper in 3 of 3 runs. The reuse-first and scoped-simplification ideas were inspired by Ponytail and the Code Simplifier agent.

## Known limits

- n=5 per risk task and n=3 per routine task, one model (Sonnet), one CLI version.
- `code_lines()` counts a single-line docstring as code. A `"""` inside a string literal drops the rest of that file from the count. Both arms are measured the same way.
- reuse-eval runs without `PLUGIN_DIR` by default, so it does not exercise the plugin's reviewer templates.
