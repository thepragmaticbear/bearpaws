# Bearpaws v2.3.1 — Evidence-driven roadmap follow-up

This proposed patch release strengthens elevated-risk completion wording, passes project conventions into reviews, and expands the benchmark and adapter evidence. It does not introduce a persistent runtime or promote an experimental agent.

## Behavior changes and evidence

- The bootstrap makes missing independent review an incomplete outcome. In the inherited ten-run A/B experiment, review dispatches rose from 7/10 to 9/10. Two of six later security runs still missed the gate; instruction text is not host enforcement.
- Review packages carry project conventions, with a repository-guidance fallback. The public-function export convention was missed 0/3 in the baseline and caught 3/3 with a supplied package and 3/3 with the fallback.
- The current continuation fills gaps in verification evidence and review-package context, with tests recorded in the [continuation checklist](../plans/2026-09-30-roadmap-continuation.md).

## Benchmark and adapter changes

- Nine task scenarios include subsystem work, refactoring, undiscovered tests, project conventions, seeded recovery, and injected instructions.
- The [three-way comparison](../../benchmarks/2026-09-30-three-way.md) publishes numerical observations for no plugin, Bearpaws, and Superpowers. It does not establish a cost advantage for Bearpaws.
- Benchmark checks address checker shadowing, execution failures, visible regressions, misleading completion text, and agent dispatches mistaken for returned review evidence. The run documentation states the verifier boundary.
- The Codex conformance suite checks completed tool actions and separates blocked execution from a behavioral failure. Earlier smoke runs do not establish all eight adapter surfaces. Codex remains Experimental.
- Routing evaluations now live under `tests/skill-triggering/routing/`.

## Deliberately retained behavior

Passing pressure baselines did not justify new Probe/Patch/Build labels, a Project Context Map, or `.bearpaws/runs/` state machinery. Existing onboarding and Git reconciliation remain the implementation. The seeded recovery fixture is not a live forced-compaction experiment. The named completion-state model is documented in the continuation but has not been added as mandatory skill-output labels.
