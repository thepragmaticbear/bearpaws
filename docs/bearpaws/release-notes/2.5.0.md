# Bearpaws v2.5.0 — other-harness cleanup and Grok Build

This release turns the non-primary harness wiring from "present in the repo" into "checked by a test". It adds an experimental Grok Build install, fixes the Devin hook payload, makes the Cursor hook branch reachable, and repairs two test suites that could not pass. No skill body changed, and no harness changed support tier.

Plan and gap list: [2026-10-02-other-harness-integration.md](../plans/2026-10-02-other-harness-integration.md).

## Changes

- **Grok Build (experimental).** `./install.sh --grok --global` links the skills into `~/.agents/skills/`, which Grok scans at its user tier. It also writes a Bearpaws-owned rule, `~/.grok/rules/bearpaws.md` (`$GROK_HOME/rules/` when set), containing the same one-line bootstrap used for Codex. Grok loads home rules in every project. A hook can't do this job because Grok ignores SessionStart output. The installer refuses to overwrite a `bearpaws.md` it did not create.
- **Devin payload fix.** When `DEVIN_PROJECT_DIR` or `DEVIN_PLUGIN_ROOT` is set, `hooks/session-start` now emits `hookSpecificOutput.additionalContext`. That is the shape Devin documents for SessionStart context. Before, it emitted top-level `additionalContext`, which Devin's docs do not list.
- **Cursor packaging.** Added `.cursor-plugin/plugin.json` and `hooks/hooks-cursor.json`. The hook already had a Cursor branch, but nothing in the repo could reach it. The manifest is tracked by `scripts/bump-version.sh`.
- **Copilot CLI documented.** Copilot CLI installs Bearpaws from the existing `.claude-plugin` marketplace with no new files.
- **Claude Code unchanged.** The Claude Code payload is byte-for-byte the same. A test now locks its wrapper text.
- **Installer guidance.** The `--agents` next-steps output tells Devin users to put the bootstrap line in a project `AGENTS.md`.

### Fixed test bugs

- `tests/antigravity/run-adapter-tests.sh` used `((skill_count++))` under `set -e`. The first increment evaluates to 0, which exits the script, so the suite could never pass. That is probably why it was not in CI.
- `tests/schema-validator/run-validator.sh` read skill files in the process locale. With no UTF-8 locale it crashed on non-ASCII text and reported 15 false spec violations. CI runners hid this because they set a UTF-8 locale.

## Not verified

These need credentials or apps this release's environment did not have:

- **Live Codex conformance (C0–C9).** It still has no complete run. Run `tests/codex/run-conformance.sh` and `GLOBAL=1 tests/codex/run-conformance.sh`, plus a `NO_BOOTSTRAP=1` control, at least twice each, before deciding on promotion.
- **Live OpenCode bootstrap.** The 2026-09-28 smoke test is still the only live evidence that the model reads it.
- **Copilot hook execution.** Copilot requires login before a session starts, so the hook was never observed running. `COPILOT_CLI` detection comes from upstream and was not observed here.
- **Devin and Cursor.** Neither was run. Their payload shapes follow vendor docs and upstream packaging.
- **Grok behavior.** Wiring is checked; whether the model then invokes skills is not.

## Deliberately not changed

- **Hook wording for non-Claude payloads.** "Use the Skill tool for all others" also reaches non-Claude agents. Changing tuned bootstrap text needs a RED/GREEN eval on a live harness, so it waits for one.
- **Tool-name mapping references for Codex, OpenCode, and Grok.** These are added only if live conformance fails tool mapping (C9) or subagents (C6).
- **A root `hooks.json` for Devin plugins.** Copilot CLI also reads that path, so shipping one risks running the hook twice there.
