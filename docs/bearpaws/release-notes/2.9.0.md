# Bearpaws v2.9.0: plan drift check and gate fixes

## Drift check before finishing

`bp:finishing-a-development-branch` now compares the code with the plan before it offers the merge, PR, keep or discard options. This applies when a plan under `docs/bearpaws/plans/` drove the branch and no final review checked the whole branch against it, which is the `bp:executing-plans` path and standalone finishes. It reports only divergences, as a `Drift:` list or "No drift.":
- behavior a task names that the code lacks;
- a planned name, field or argument that is missing or hardcoded;
- a source change no task covers.

After a fix, it returns to the test run. It runs in the agent finishing the branch, with no extra subagent or hook. The idea comes from the Elephant-Goldfish Model's drift report (egm.dev). EGM's goldfish reviewer isolation was not adopted: `bp:requesting-code-review` already isolates reviewers partly (crafted context, never session history, with the author's claims labeled as claims rather than withheld). Its five-stage spec review loop was not adopted, because it would add review passes.

**Evidence (`tests/drift-eval`, Sonnet, n=3).** The fixture is a branch with every task checked off and all tests passing, but one task was never built, an argument is hardcoded, and one file is unplanned.

| Skill text | Divergences found | "No drift" on a clean branch with a README and changelog no task names |
|---|---:|---:|
| Before the change | 0/3 runs | |
| After the change | 3/3 runs, all three divergences | 3/3 |

The scorer reads only the `Drift:` block. `test_score.py` pins it and runs in CI.

## Gate fixes

- **Pre-push identity check:** a flag now covers one remote, branch and set of commits. New commits on a flagged branch are flagged again. A push to another remote checks commits already flagged elsewhere until that remote has them, so a "proceed" to a private fork no longer clears them for the public upstream. Flag lines from v2.8.x don't match the new format, so a branch flagged before the upgrade is flagged once more.
- **Sensitive-path heuristic:**
  - `session`, `token`, `schema` and `price` still match anywhere in a path.
  - A few ordinary words are removed before matching: `tokeniz`, `schemati` and `priceless`. `tokenizer.py` stays quiet, and `tokenstore.go` and `pricecalc.go` still nudge.
  - This also means `card_tokenizer.go` no longer matches unless its path names payment or billing.
- **`risk-gate`:** the test-run pattern is built from named pieces and is byte-identical to the old pattern.
- **README:** the risk-gate section now lists the gate's known limits. A failing test run counts as a run, and so does a heredoc or commit-message line that starts with a runner name.
- **CI:** runs `shellcheck -S warning` over the hooks (except the `run-hook.cmd` polyglot), `install.sh` and `scripts/`.

## Junie (experimental)

`./install.sh --junie --global` links skills into `~/.junie/skills` and prints the bootstrap line for `~/.junie/AGENTS.md`. It never edits that file.

## Known limits

- The drift eval uses one fixture shape and one model at n=3. No eval covers the rule that skips the check after a whole-branch final review.
- Pre-push minor issues found in review:
  - A push to a bare URL re-flags already-pushed flagged commits on each new tip.
  - A backslash in a URL remote never proceeds.
  - A remote named with a `/` can shadow another remote's tracking refs.

  All of these fail closed or are rare. `--no-verify` bypasses them.
- mawk 1.3.3 and Windows git-bash were not tested.
