# Bearpaws v2.6.0: an enforced risk floor, and evidence for it

In Claude Code, the elevated-risk rule is now enforced by a hook rather than only requested. This release also adds a pre-registered benchmark that measures risky defects shipped, and a skill change that fixes the main failure that benchmark found.

## Risk gate and risk receipt (Claude Code only) — #18

- **Risk receipt.** Every reply that changed files ends with `Risk:`, `Verified:` and `Status:`. Elevated work adds `Pinned:`, `Failing first:`, `Review:` and `Assumptions:`. The receipt is defined in `bp:using-bearpaws` and `bp:verification-before-completion`.
- **`hooks/risk-gate`** runs on `PostToolUse` and `Stop`. At Stop it blocks a reply in two cases:
  - edits are pending and the reply has no receipt;
  - the reply ends elevated-risk work as `Status: COMPLETE`, but no review was dispatched after the last edit.

  `Status: INCOMPLETE` is always allowed.
- **Pending edits.** Edits stay pending across turns, including background-subagent report-backs, until a receipt accepts them.
- **Sensitive paths.** Routine work that edits sensitive-looking paths gets one nudge to reclassify the change or say why it is routine.
- **Requirements and limits.**
  - Needs `jq`. Without it, the gate allows the reply and logs a note to stderr.
  - It is a no-op outside Claude Code: Copilot CLI, Cursor and Devin get exit 0. Set `BEARPAWS_ENFORCE=0` to disable it.
  - It does not record edits made through the Bash tool, and it does not check that receipt lines are true.
- **Tests.** `tests/hooks/run-risk-gate-tests.sh` pins each rule, and CI runs it.

## Escaped-defect benchmark — #19

- **Runner.** `tests/benchmark/run.sh --suite risk` runs six elevated-risk scenarios. Each has hidden attack tests that the agent cannot read.
  - Isolation uses a Seatbelt sandbox, checker snapshots and fingerprints.
  - Results are scored as `escaped`, `disclosed` and `incomplete`.
  - `check_scenarios.py` validates each scenario without a model, and CI runs it.
- **Pre-registered result.** The run was frozen at tag `prereg/escaped-defects-8ba4601`. Escaped defects: Bearpaws 9/30, no plugin 12/30, Superpowers 6.4.2 12/30. The difference is not significant (p = 0.59).
- **Main finding.** In 7 of the 9 Bearpaws escapes, its own reviewer flagged the defect and the agent shipped it anyway. See [the write-up](../../benchmarks/2026-10-12-escaped-defects.md).

## Review findings are part of the fix — #20

- **New rule.** One new sentence in the bootstrap's elevated-risk rule: a defect the review finds in the same risk class, in the code you changed, is part of the fix. Fix it with its own failing test, or end `Status: INCOMPLETE` and name it.
- **Effect.** On the same frozen scenarios, Bearpaws escapes fell from 9/30 to 3/30 (p = 0.10). This was a same-arm before/after comparison, not pre-registered.
  - The SQL-sort and tenant-authz escapes dropped to 0, mostly because the agent's first fix was broader.
  - All 3 remaining escapes are the reset-token single-use attack.
  - The narrow-diff eval still scores 3/3.
  - Cost per task rose about 33%.
- **Routine path.** It was investigated and ships no skill change. Routine runs never invoked brainstorming, and the expected saving was about $0.004 per task. The benchmark summary now counts skill use per arm, and the routing eval supports forbidden-skill checks.

## Upgrade notes

- **Size.** The bootstrap grew from 4,381 to 4,876 bytes.
- **Cost.** Expect higher cost and longer runs on elevated-risk work. Most of it comes from independent reviews and post-review fixes. Routine work is about level with Superpowers.
- **Turning it off.** If the Stop hook gets in your way, set `BEARPAWS_ENFORCE=0`.
- **Known follow-ups:**
  - whether a fix made after review needs a re-review;
  - recording Bash-tool edits in the gate;
  - a per-session timeout in the benchmark runner;
  - the scorer reading the last `Status:` line across all of a session's replies.
