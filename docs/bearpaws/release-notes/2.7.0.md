# Bearpaws v2.7.0 — a git-level risk gate, and less over-building

This release brings the risk-receipt floor to any agent or person that commits through git, not only Claude Code. It also cuts the extra code Bearpaws wrote on elevated-risk work, and it prepares the plugin for the Claude plugin directory.

## Git gate (`hooks/git-commit-msg`, `install.sh --git`) (#37)

- **New `commit-msg` hook.** A commit with staged changes and no `Risk:` line is refused. An elevated commit also needs a `Review:` line or `Status: INCOMPLETE`. A routine commit that touches sensitive-looking paths gets a one-line warning. The receipt can sit in trailers or in the body.
- **Skipped:** empty commits, real merges, `fixup!`/`squash!` subjects and empty messages. Comment lines and everything below the `git commit -v` scissors line are ignored; comment detection follows `core.commentChar` and `core.commentString`.
- **Install:** run `./install.sh --git` inside a repository. It follows `core.hooksPath` and linked worktrees, and it refuses to overwrite a hook it did not write.
- **Requirements:** bash and git 2.31 or later. No `jq`.
- **Bypass:** `git commit --no-verify` or `BEARPAWS_ENFORCE=0`.
- **Shared format:** `hooks/lib-receipt` holds the receipt regex and the sensitive-path list for both `risk-gate` and the git gate. `risk-gate` behaves the same as in 2.6.1.

**Honest limit:** git sees a claimed review, not a dispatched one. Only the Claude Code hook can check that a review actually ran.

## Less over-building on elevated-risk work (#36)

- **Bootstrap.** A defect is behavior a caller in this codebase or a user's input can reach, so a negative or oversized amount is one. A guard for a type no caller passes (NaN, bool, a string timestamp) is not, and the review is not asked for one.
- **Reviewer templates.** "SOLID" and the scalability and extensibility prompts are gone. Generality the requirements do not need is an Important finding whose fix is deletion. Hardening against an actor outside the task's threat model is Minor.
- **Measurement.** The benchmark now records diff size against the reference fix and prints a bloat ratio. `tests/review-eval` gains the `minimal`, `overbuilt`, `traversal`, `refund` and `refund-narrow` fixtures.

## Plugin directory readiness

- Plugin icon at `.claude-plugin/icon.png` (#32) and `displayName` set to Bearpaws (#33).
- `PRIVACY.md` describes what the plugin stores and sends: nothing over the network, and only the `risk-gate` hook's local files (#34).
- `.gitattributes` removed so installed files match the repo (#31). On Windows, a clone with `core.autocrlf=true` can get CRLF line endings in the hook scripts.
- Repo URLs point at `thepragmaticbear/bearpaws` (#30).

## Known limits

- A clean cherry-pick or revert never runs `commit-msg`, so the git gate does not see it.
- `git merge --squash` picks up the receipts of the commits it squashes.
- The git gate always strips comment lines, so with `--cleanup=verbatim` a `#Risk:` line is not counted. This can only block a commit, never let a missing receipt through.
- The two git-gate sentences in `verification-before-completion` and `finishing-a-development-branch` went in without a RED/GREEN eval.
