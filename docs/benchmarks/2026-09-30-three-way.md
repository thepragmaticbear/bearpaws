All three arms passed the original 27/27 acceptance checks. After correcting duplicate cumulative cost records, Bearpaws cost 15% more than Superpowers and 74% more than the no-plugin arm. Its added process included independent reviews on four of six security runs; two security runs still missed that gate. ## Process observations

The original scorer counted Agent/Task dispatches, not completed review verdicts. Rescoring the actual tool calls and returned results identifies five review requests and five returned reviewer outputs for Bearpaws: the multi-file refactor (one), security fix (one), and injected security fix (three). No security run in either comparison arm dispatched an agent. A returned output establishes review participation, not automatic approval or proof that every adversarial gate was satisfied.

Bearpaws security-fix runs 1 and 3 ended without a review and without declaring the required gate incomplete. Passing the fixture's acceptance checks does not make these runs Independently Verified. The review-gate counts apply Bearpaws' elevated-risk policy uniformly for comparison; they are not claims that Superpowers violated its own policy.

The earlier fail-closed wording A/B experiment accepted all 20 security tasks. The original scorer observed review dispatches in 7/10 old-bootstrap runs and 9/10 new-bootstrap runs. This small experiment justified keeping the targeted wording, but the later three-way run shows that instruction text alone does not enforce every review gate.

## Stronger checker revalidation

On 2026-09-30 the controller reran strengthened acceptance checks and visible suites against all 81 saved worktrees without additional model calls. All three arms still passed 27/27. Checks now catch a sliding TTL, uncommitted rewrites of completed work, fake logger comments, changed frozen legacy files, and callers bypassing the shared formatter.

[Corrected and revalidated per-run observations](2026-09-30-three-way-revalidated.csv) preserve costs after cumulative-session deduplication, original token segments, returned-review evidence, and the new acceptance results. Source logs live separately under `/tmp/bearpaws-tests/benchmark/three-way/revalidated-v2/`; the original logs and streams remain unchanged.

This confirms the saved outputs satisfy the stronger fixtures. It does not establish that historical agents lacked access to check definitions, that historical source definitions were protected, or that the CLI returned exit 0: those historical boundary fields remain unknown. New runs use native macOS process confinement plus verifier snapshots and integrity checks; unsupported hosts need an explicit unisolated mode labelled `integrity_only`.

## Practical limits

1. Three runs per cell and small, fully specified tasks cannot establish superiority, statistical reliability, or the cost of interactive design approval. Treat the result as a smoke benchmark.
2. The recovery fixture seeds interrupted Git state and a stale summary. It tests recovery reconciliation, not actual host compaction, preservation of every unresolved ruling, or repeated-work counts.
3. Acceptance-test pass fraction is test coverage of this fixture, not general requirement coverage. These examples are all Python and do not measure broad stack support.
4. The inherited runner keeps acceptance definitions outside the task worktree, but `bypassPermissions` leaves the source reachable and writable. These runs did not provide host-enforced checker isolation. Later integrity checks cannot retroactively certify the old run.
5. Process heuristics require transcript inspection. Dispatching any agent is insufficient evidence of independent review; a missing required gate remains incomplete even when code passes acceptance.

## Reproduce

From a fresh checkout of this branch and a separate Superpowers checkout at the recorded revision:

```bash
SUPERPOWERS_DIR=/path/to/superpowers tests/benchmark/run.sh \
  --runs 3 --arms "baseline bearpaws superpowers" --model sonnet \
  --budget 5 --jobs 3 --out /tmp/bearpaws-three-way-repeat
python3 tests/benchmark/summarize.py /tmp/bearpaws-three-way-repeat/results.jsonl
```

Future runs use the revised scoring and integrity checks; compare their process fields with their documented definitions rather than silently combining them with the inherited heuristic fields.
